### 关键方法

```python
async def generate(
    self,
    prompt: str,

    temperature: Optional[float] = None,
    **kwargs

```

- `AnthropicProvider` - Claude 系列

### 设计意图

- ✅ **多 LLM 后端支持**：通过 Protocol 实现鸭子类型
- ✅ **无需继承**：任何实现这些方法的类都兼容
- ✅ **可测试性**：易于 Mock 测试
- ✅ **配置驱动**：通过环境变量切换提供者

### 为什么用 Protocol 而非 ABC？

- Protocol 支持结构化子类型（Structural Subtyping）
- 不需要显式继承，只要方法签名匹配即可
- 更灵活，适合集成第三方库

| **Generic Repository** | 数据访问 | `BaseRepository[T]` |

## 设计原则体现

### SOLID 原则

1. **S (单一职责原则)**
   - 每个抽象职责单一（Repository 只管数据访问）
   - Converter 只负责数据转换
   - Extractor 只负责记忆提取

2. **O (开闭原则)**
   - 扩展开放（新增 LLM Provider 无需修改现有代码）
   - 修改封闭（新增检索策略不影响现有策略）

3. **L (里氏替换原则)**
   - 所有 Repository 实现可互换
   - 所有 LLM Provider 可互换
   - 所有 Vectorize Service 可互换

4. **I (接口隔离原则)**
   - `VectorizeService` 和 `RerankService` 分离
   - `MemCellExtractor` 和 `MemoryExtractor` 分离
   - 每个接口只包含必要的方法

5. **D (依赖倒置原则)**
   - 业务层依赖抽象，不依赖具体实现
   - 高层模块不依赖低层模块
   - 所有依赖通过 DI 容器注入

---

### DRY (Don't Repeat Yourself)

- Base Repository 避免每个 Repo 写重复 CRUD
- BaseVectorizeService 提供通用批处理逻辑
- BaseController 提供统一路由注册机制

---

### 可测试性

- 所有抽象都可 Mock
- Protocol 类型支持结构化子类型，无需继承
- 纯函数式接口易于单元测试

---

### 性能优化

- **批量操作方法**：`create_batch`, `get_embeddings_batch`
- **Async I/O 统一**：所有方法都是 `async def`
- **连接池管理**：数据库连接复用
- **批处理**：减少网络往返

---

### 成本优化

- **Hybrid Services**：Primary (自部署) + Fallback (商业 API)
- **失败时自动切换**：节省 API 费用
- **优先自部署**：降低长期运营成本
- **按需降级**：主服务不可用时才使用付费服务

## 总结

EverMemOS 的核心抽象层设计体现了以下特点：

1. **清晰的分层架构**：数据访问、业务逻辑、服务编排层次分明
2. **高度可扩展**：新增功能无需修改现有代码
3. **类型安全**：大量使用泛型和类型提示
4. **多后端支持**：统一接口适配多种外部服务
5. **性能优先**：批量操作、异步 I/O、连接池
6. **成本优化**：自部署优先，付费 API 作为备用
7. **测试友好**：所有抽象都可 Mock，易于单元测试
8. **生产就绪**：完善的错误处理、重试、超时机制

这些设计使得 EverMemOS 能够在保持代码质量的同时，支持快速迭代和功能扩展。
